## 2. Lineage
- **Dinghy platform** (zvenson) with Felucca / SLOOP HAL. `platform.c`, `tests/host.c`, `dinghy.c` (Dinghy's demo app,
  still in the tree), app `fm106.c` + `fm106_*.h`. Engine from **ultramaster_kr106** (Juno-106: DCO, IR3109 ladder,
  D7811G ADSR, MN3009 chorus). Dual-core worker "adapted from Melodee" (`audio_worker.h`, `hal/fm1_multicore.h`,
  `DINGHY_DUAL_CORE`).

## 3. Host builds
- **Native host sim**: `tests/host.c` (`DINGHY_HOST`), headless and script-driven (`tests/script_a*.txt`), writes PPM +
  WAV (`tests/run_host.sh`). Plus `tests/audio_worker_test.c` and `audio_worker_thread_test.c` (pthread).
  - This host.c is a **stripped** Dinghy host: `fm1_enc_take()` always returns 0 (no knobs), `fm1_input_edges` never
    reports releases, `fm1_led_key` is a no-op, and `presets_flash_*` are stubs. It is good for audio renders, not as a
    panel.
- **No WASM sim in the repo** (`web/` and the root hold installer / librarian pages and a prebuilt `.fwsc`). Any hub
  player would be the hub's own build.
- Panel (Dinghy): BTN OCT- OCT+ FX SEL ENV LFO EDIT GLO HOME SAVE ARP SEQ PLAY REC; ENC SELECT ALGO K1..K4 PRESETS;
  `fm1_in.notes` 27 bits; LED ids 0..13 / 14 + key; 240x240 RGB565 fb.

## 4. Build steps
- Nothing generated: `firmware/gen/felucca_font.h` and `fm106_tables.h` / `fm106_fx_tables.h` are committed
  (`tools/gen_fm106_data.py`). No Pillow. No assets. No `generate()` in `tools/build.py`.
- Version: `APP_VER` from `build.py --release`. Pass `-DAPP_VER="Beta4"`.

## 5. Blockers for a native macOS build
- **The upstream host build is broken at Beta4** (19 errors with Apple clang): `section(".pool")` in `fm106_fx.h`;
  `str_cpy` (libc.c is not in the host unit); `fm106_now_ms` and `fm1_adc_read` / `FM1_ADC_BATT` (device branch only);
  `uac.alt/starts/stalls/rate_sets/missed/flowing` and `audio_lates` (not in host.c's fakes). The host mode bit-rotted
  while the app grew.
- `platform.c` includes `../../tests/host.c` by a relative path with no guard, so a glue cannot swap the host from
  outside without (a) clang's `-ivfsoverlay` (maps `tests/host.c` to a glue file; verified working here), or (b) a
  staged copy of `firmware/src` next to a glue `tests/host.c`.
- Dual core: `DINGHY_DUAL_CORE` is only defined in the device branch; on the host `audio_worker_online` is 0 and the
  engine renders inline. Fine for a core.
- **Float** in `fm106_fx.h` (biquads, tape, flutter: `float` arithmetic, with its sine from a table rather than libm).
  This is soft-float on the chip and native on the Mac, so the sound will match closely but not bit for bit. The rest
  is integer.
- Never-returning `app_main`: the Dinghy coroutine need.

## 6. Persistence and audio
- Device NOR: settings record (<= 256 B) at `0xFC000`; user presets `FM106_PRESETS_FLASH_ADDR 0x98000`, 8 KiB (2
  sectors, erased and rewritten as one blob); OTA `0xE0000`. host.c stubs the preset flash (reads fail, saves dropped).
  The core needs its own `presets_flash_read` / `save` over the image, which is easy since `platform.c`'s device
  versions are three lines over `st_read` / `fl_erase4k` / `fl_write`.
- Audio: 44.1 kHz, stereo Q15, 256-frame blocks (the dual-core path requires n == 256).

## 7. Host sim tried
- As shipped: does not compile (19 errors, listed above).
- With a 6-line shim in an overlaid copy of `tests/host.c` (`-ivfsoverlay`, plus `-D'section(x)=aligned(4)'`): builds
  with Apple clang and runs `script_a21_held.txt` headless. `a21.wav` (485 k frames, peak 6957); the screen shows the
  Juno UI (A21 Organ I, VCF sliders, the scope). Shim:
  `hubbuild/fm106/ovl/host.c` + `vfs.yaml`.

## 8. FM1VST glue
- Closest existing: none; it is a **Dinghy glue** (the OberVave / Frodhes family). It needs the overlay route because
  its host.c is unusable as a panel. The glue's own host.c would provide the real input / LED / flash HAL and the
  missing symbols.
- Effort: **M** (S on top of a finished Dinghy glue plus the overlay mechanism and the bit-rot shim).
- Risks: an upstream that commits binaries and keeps two source trees (pin `firmware/src`); host mode not maintained
  upstream, so every release may break the shim; float FX; KR-106 provenance / licence to verify; "Beta4" naming (the
  version regex has no source file to read).
